# Domain-Model.md

# BrkRoutnXdle Domain Model

## Purpose

This document exclusively describes the application domain.

It does not contain infrastructure, frontend, backend, or external integration details.

Its goal is to define:

* Entities
* Value Objects
* Relationships
* Business Rules
* Invariants

---

# Domain Overview

The domain consists of automatically generating a weekly schedule from:

* Task definitions
* Constraints
* Preferences
* Availability found in Google Calendar

The result is a set of events distributed throughout the week.

---

# Core Concepts

## Task

Represents a recurring activity defined by the user.

A Task does not represent a specific event.

A Task represents a generation rule.

### Properties

```ts
type TaskPriority =
  | "low"
  | "medium"
  | "high"
  | "critical";

type Task = {
  id: string;

  name: string;

  durationMinutes: number;

  timesPerWeek: number;

  occurrencesPerWeek: number;

  priority: TaskPriority;

  blockedWeekDays: WeekDay[];

  blockedPeriods: Period[];

  startDate?: string;

  endDate?: string;

  createdAt: string;

  updatedAt: string;
};
```

---

## Generated Event

Represents an occurrence generated by the algorithm.

A Task generates multiple Generated Events.

### Properties

```ts
type GeneratedEvent = {
  id: string;

  taskId: string;

  calendarEventId: string;

  start: string;

  end: string;

  completed: boolean;

  completedAt?: string;

  createdAt: string;

  updatedAt: string;
};
```

---

## Blocked Slot

Represents an unavailable period.

### Properties

```ts
type BlockedSlot = {
  id: string;

  type:
    | "single-day"
    | "recurring-weekday"
    | "recurring-period";

  start: string;

  end: string;
};
```

---

## Settings

Represents global preferences.

### Properties

```ts
type Settings = {
  shuffleEnabled: boolean;

  weekStartsOn:
    | "monday"
    | "sunday";

  availableStartHour: string;

  availableEndHour: string;
};
```

---

## Week

Represents the week used by the algorithm.

### Properties

```ts
type Week = {
  start: string;

  end: string;
};
```

---

## Week Slot

Represents a minimum unit of availability.

### Properties

```ts
type WeekSlot = {
  start: string;

  end: string;

  occupied: boolean;

  blocked: boolean;
};
```

---

## Availability Window

Represents an available interval.

### Properties

```ts
type AvailabilityWindow = {
  start: string;

  end: string;
};
```

---

## Previous Week Snapshot

Represents the previous week used to avoid repetitions.

### Properties

```ts
type PreviousWeekSnapshot = {
  generatedEvents: PreviousWeekEvent[];
};
```

### Previous Week Event

```ts
type PreviousWeekEvent = {
  taskId: string;

  start: string;

  end: string;
};
```

# Domain Invariants

## INV-001

Task duration must be a multiple of 30.

---

## INV-002

Task duration must be greater than zero.

---

## INV-003

TimesPerWeek must be greater than zero.

---

## INV-004

Task name cannot be empty.

---

## INV-005

Events cannot be generated outside Available Hours.

---

## INV-006

Events cannot be generated during blocked times.

---

## INV-007

Events cannot collide with busy events.

---

## INV-008

Events started before the current moment cannot be recalculated.

---

## INV-009

Events from the previous week must not repeat the exact same slot when shuffle is active.

---

## INV-010

Completed events must not be recalculated.

---

# Ubiquitous Language

## Task

---

## Generated Event

Occurrence produced by the algorithm.

---

## Blocked Slot

Explicitly unavailable period.

---

## Week Slot

Smallest time unit used by the algorithm.

---

## Availability Window

Free window for allocation.

---

## Previous Week Snapshot

Representation of the previous week used to avoid repetition.

---

## Shuffle

Random distribution mode.

---

## Recalculate Week

Process of reorganizing future events of the current week.

# Domain Boundaries

The domain is NOT responsible for:

* OAuth
* Google APIs
* Persistence
* React
* Express
* Cache
* FullCalendar
* LocalStorage
* Infrastructure

These elements belong to the application and infrastructure layer.
