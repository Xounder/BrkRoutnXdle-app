# Event-Classification.md

# BrkRoutnXdle Event Classification System

## Purpose

This document defines how events are classified within the system.

The goal is to eliminate ambiguities between:

- user events
- system-generated events
- external Google Calendar events
- schedule blocks

---

# Core Principle

```text
Every calendar entry must have a deterministic classification.
```

---

# Event Types

## EventType Enum

```ts
type EventType =
  | "task"
  | "external"
  | "blocked"
  | "system";
```

---

# 1. Task Event

Event generated from a system Task.

## Characteristics

```text
Created by scheduling engine
Represents a planned activity
Can be rescheduled
Linked to a Task
```

---

# 2. External Event

Event coming from Google Calendar that does not belong to the system.

## Characteristics

```text
Created outside the app
Read-only for scheduling engine
Occupies time slots
```

---

# 3. Blocked Event

Event created by the user explicitly to block time.

## Characteristics

```text
User-defined constraint
Represents unavailable time
Overrides scheduling
```

---

# 4. System Event

Internal system events that do not represent actual tasks.

## Characteristics

```text
Generated by system logic
Used for metadata or tracking
May be invisible to user UI
```

---

# Classification Rules

## Rule 1: External Detection

```text
If event comes from Google Calendar AND lacks system metadata → external
```

---

## Rule 2: Task Detection

```text
If event has taskId → task
```

---

## Rule 3: Blocked Detection

```text
If event originates from user block input → blocked
```

---

## Rule 4: System Detection

```text
If event has extendedProperties.app = "BrkRoutnXdle-system" → system
```

---

# Metadata Contract

All system-managed events MUST include:

```ts
extendedProperties: {
  private: {
    app: "BrkRoutnXdle",
    type: EventType,
    generated: "true" | "false",
    taskId?: string,
    createdAt: string,
    updatedAt: string
  }
}
```

---

# Priority Between Event Types

## Hierarchy

```text
blocked > external > task > system
```

---

## Explanation

### Blocked

Always wins

---

### External

Cannot be overridden

---

### Task

Can be moved or regenerated

---

### System

Lowest priority, purely informational

---

# Mapping from Google Calendar

## Google Event → Internal Type

```text
No metadata → external
Has app=BrkRoutnXdle → task or system
User block → blocked
```

---

# Consistency Rules

## Rule 1

Event type must never change implicitly.

---

## Rule 2

Classification must be deterministic.

---

## Rule 3

No event can belong to multiple types.

---

## Rule 4

Google Calendar is always source of truth for external events.

---

# Success Criteria

The classification system is valid when:

1. Every event has exactly one type
2. No ambiguity exists between task/external/blocked/system
3. Scheduling engine respects hierarchy rules
4. External events are never modified
5. Blocked events always override scheduling
6. System events do not affect real scheduling logic
7. Mapping from Google Calendar is deterministic
